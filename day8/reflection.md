Project Reflection: TicketHub Event Ticketing System

Working on TicketHub allowed me to learn how the various components of a web application can come together to solve a real-world problem. I found myself learning that there is much more to website system design than just building a site. It involves thinking through how the users will interact with the system and how information will be stored and what will happen if there is more traffic.

Perhaps the most significant lesson was the knowledge that there was a difference between normal and peak traffic. At the concert show, I was exposed to the need for a system to be designed to cope with rapid surges in request volume. I also got to know about how API's link the front end with the back end, and the role of Primary key and Foreign key in a database table.

The hardest thing I found out was how to avoid double booking. I learned about the following features that help prevent two customers from successfully purchasing the same seat: Temporary seat reservations, Database transactions, Unique constraints

I also thought about trade-offs when it comes to selecting a virtual waiting queue, Redis caching and a relational database. The decisions made are a balance between performance, reliability and complexity.

Overall, all of this helped me understand more about system design, database, APIs, and scalability. Now I have a better understanding of how to think about designing a system before I write code for the application.
